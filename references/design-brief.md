# Проект «Маршрут»

## Задача

Создать красивое адаптивное веб-приложение для подготовки к путешествию. Пользователь должен видеть основные данные о поездке, маршрут, бюджет, бронирования, чек-лист и ближайшие действия.

Это учебный проект. Все даты, суммы, адреса и бронирования являются демонстрационными данными.

## Демонстрационная поездка

- Название: «Лиссабон и океан».
- Даты: 12–18 сентября.
- Продолжительность: 7 дней.
- Маршрут: Лиссабон → Кашкайш → Синтра → Эрисейра → океан → Лиссабон.
- Общий бюджет: 180 000 рублей.

## Основные блоки

### 1. Обложка поездки

Показывает:

- название поездки;
- даты;
- количество дней;
- обратный отсчёт;
- декоративную линию маршрута с точками.

Не использовать внешние изображения в готовом приложении. Обложку нужно создать с помощью CSS-градиентов, простых форм и встроенного SVG. Файл `visual-reference.png` служит только визуальным ориентиром.

### 2. Темп путешествия

Переключатель:

- «Спокойно»;
- «Насыщенно».

При переключении должны изменяться:

- количество событий в выбранном дне;
- примерная стоимость дня;
- текстовая подсказка;
- общий прогноз расходов.

### 3. Маршрут по дням

Пользователь выбирает день и видит:

- город;
- дату;
- время;
- название события;
- категорию;
- стоимость;
- статус бронирования.

### 4. Бюджет

Показывает:

- общий бюджет — 180 000 рублей;
- запланированную сумму;
- остаток;
- круговой или линейный прогресс;
- категории расходов.

### 5. Бронирования

Карточки:

- перелёт;
- отель;
- поезд;
- экскурсия.

Для неподтверждённого бронирования должна быть кнопка «Подтвердить». После нажатия статус меняется, а на экране появляется небольшое уведомление.

### 6. Чек-лист подготовки

Категории:

- документы;
- деньги;
- вещи;
- здоровье.

Отметки должны сохраняться после перезагрузки страницы через `localStorage`. Добавить кнопку «Сбросить учебные данные».

### 7. Мобильный режим «Сегодня»

На узком экране главный акцент переносится на:

- текущий день;
- ближайшее событие;
- место;
- время;
- статус бронирования;
- следующую задачу из чек-листа.

Добавить компактную нижнюю навигацию: «Сегодня», «Маршрут», «Бюджет», «Подготовка».

### 8. Состояния интерфейса

Нужно реализовать:

- `loading` — карточки-скелетоны;
- `error` — понятное сообщение и кнопка «Повторить»;
- `empty` — день без событий;
- `success` — обычное рабочее состояние.

Для записи и проверки добавить сворачиваемую панель «Демо состояний».

## Визуальный стиль

Ориентироваться на `visual-reference.png`, но не пытаться копировать изображение пиксель в пиксель.

- светлый тёплый фон;
- белые карточки;
- основной текст — тёмно-синий;
- главный акцент — фиолетовый;
- дополнительные акценты — морской синий и коралловый;
- зелёный — успешные действия;
- жёлтый — ожидание;
- красный — ошибка;
- скруглённые карточки 18–24 пикселя;
- мягкие тени;
- крупные заголовки и удобные кнопки;
- единая система отступов;
- спокойная современная эстетика путешествий;
- без перегруженного интерфейса обычной административной панели.

## Адаптивность

Проверить три контрольные ширины:

- 1440 пикселей — полноценная двухколоночная версия;
- 768 пикселей — компактная планшетная компоновка;
- 390 пикселей — мобильный режим «Сегодня».

Не должно быть горизонтальной прокрутки, наложения элементов и слишком мелкого текста.

## Технические ограничения

Использовать только:

- HTML;
- CSS;
- JavaScript.

Не использовать:

- React, Vue и другие фреймворки;
- npm и сборщики;
- внешние библиотеки и CDN;
- базы данных;
- авторизацию;
- внешние API;
- загрузку данных из интернета.

Структура приложения:

- `app/index.html`;
- `app/styles.css`;
- `app/app.js`.

Приложение должно работать после обычного открытия `index.html` в браузере.

## Критерии готовности

1. Все основные блоки присутствуют и визуально согласованы.
2. Переключение темпа меняет расписание и прогноз бюджета.
3. Переключение дня обновляет маршрут без перезагрузки.
4. Бронирование можно подтвердить, после действия появляется уведомление.
5. Чек-лист и бронирования сохраняются через `localStorage`.
6. Кнопка сброса возвращает учебные данные в исходное состояние.
7. Реализованы `loading`, `error`, `empty` и `success`.
8. Мобильный режим показывает ближайшее действие в первую очередь.
9. Проект не использует сеть или платные сервисы.
